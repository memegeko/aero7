# Dell Latitude 3310 hardware test — 2026-08-09

## Scope

- candidate: `aero7-beta1-2026.08.09-x86_64.iso`;
- candidate SHA-256: `cea0f8db6957852169031792ce77315bdf0599795126d78c5c5bd9777bd7976c`;
- installer source at build: `35654eda848c023e879f6054858c2e822f5e05a0`;
- machine: Dell Latitude 3310, x86-64 UEFI, 238.5 GiB NVMe target;
- boot path: Ventoy GRUB2 mode;
- storage firmware setting: AHCI rather than Intel RAID/RST;
- test type: destructive whole-disk installation on a disposable target.

## Result

The candidate booted, discovered the NVMe target, created a 1 GiB FAT32 EFI
System Partition and a 237.5 GiB ext4 root partition, downloaded the complete
1,622.28 MiB package transaction, installed 717 packages, configured
systemd-boot, completed OOBE, and reached the Aero7 Plasma desktop.

A read-only post-install audit confirmed:

- Linux 7.1.6 running from the installed NVMe root;
- the `Aero7` systemd-boot entry selected and booted from the NVMe ESP;
- NetworkManager connected over the machine's wired interface;
- SDDM, Plasma Wayland, KWin, and plasmashell active;
- the expected AeroShell, AeroThemePlasma, Aero7 application, SDDM, and
  Plymouth packages installed;
- `/var/lib/aero7/oobe-complete` and the install-source/package-request records
  present;
- zero failed systemd units.

## Findings and follow-up

This is a successful first physical-hardware installation, not yet a formal
hardware-support sign-off.

- The candidate's time-based base-system meter reached 99% while pacstrap was
  still downloading. Commit `5a03113` replaces that with measured cache-byte
  progress for the next image.
- The live `/var/log/aero7-installer.log` was not copied to the target and was
  lost at reboot. The next candidate preserves installer, storage-action, and
  partition-table logs under the installed `/var/log` with mode `0600`.
- The installed system still identified itself as plain Arch Linux and lacked
  the traditional `hostname` utility. The next candidate writes an Aero7
  `os-release` with `ID_LIKE=arch` and installs `inetutils`.
- Plasma's Aero lock screen inherited black button text. The next candidate
  reapplies the current Aero7 wordmark and forces readable white button labels.
- The boot journal contained non-fatal AeroShell widget warnings. They require
  a separate shell/package cleanup and a repeat journal review.

Repeat the same destructive Dell test with the next fully gated image and
archive its retained installer log before advertising physical-hardware
support.
